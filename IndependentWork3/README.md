# Звіт з аналізу інкапсуляції в Open-Source проєкті

## 1. Обраний проєкт

**Назва:** .NET Runtime

**GitHub:** https://github.com/dotnet/runtime

**Мова програмування:** C#

.NET Runtime — відкритий проєкт Microsoft, який містить реалізацію .NET Runtime та стандартних бібліотек.

Для аналізу обрано два класи: `List<T>` та `DateTime`.

## 2. Аналіз інкапсуляції

### Клас List<T>

**Файл:** https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Collections/Generic/List.cs

`List<T>` використовується для зберігання набору об'єктів. Внутрішній стан класу не призначений для прямого використання звичайним користувачем.

Для зберігання елементів використовуються внутрішні поля:

```csharp
internal T[] _items;
internal int _size;
internal int _version;
```

Ці поля мають модифікатор `internal`, тому вони не є частиною звичайного публічного інтерфейсу класу. Доступ до даних для користувача здійснюється через властивості, методи та індексатор.

Кількість елементів доступна через властивість тільки для читання:

```csharp
public int Count => _size;
```

Користувач може отримати кількість елементів, але не може змінити `Count` напряму.

Також використовується індексатор:

```csharp
public T this[int index]
{
    get
    {
        if ((uint)index >= (uint)_size)
        {
            ThrowHelper.ThrowArgumentOutOfRange_IndexMustBeLessException();
        }

        return _items[index];
    }
}
```

Перед доступом до елемента перевіряється правильність індексу. Користувач не має прямого доступу до внутрішнього масиву `_items`.

Таким чином, `List<T>` використовує інкапсуляцію для контролю доступу до внутрішнього стану колекції.

### Клас DateTime

**Файл:** https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/DateTime.cs

`DateTime` використовується для представлення дати та часу.

Внутрішній стан об'єкта зберігається у приватному полі:

```csharp
private readonly ulong _dateData;
```

Користувач не може безпосередньо змінити `_dateData`.

Доступ до даних здійснюється через властивості тільки для читання. Наприклад:

```csharp
public long Ticks => (long)(_dateData & TicksMask);
```

Клас також перевіряє вхідні значення:

```csharp
if ((uint)kind > (uint)DateTimeKind.Local)
{
    ThrowInvalidKind();
}
```

Якщо передано некоректне значення, викликається метод, який генерує виняток.

Таким чином, `DateTime` приховує внутрішнє представлення дати та контролює правильність даних.

У проаналізованих класах основний акцент зроблено на властивостях, які повертають дані з внутрішніх полів. Автоматичні властивості у наведених прикладах не використовуються.

## 3. Практики валідації

У проаналізованих класах валідація виконується безпосередньо в коді за допомогою умов та винятків.

### Приклад 1 — List<T>

```csharp
if ((uint)index >= (uint)_size)
{
    ThrowHelper.ThrowArgumentOutOfRange_IndexMustBeLessException();
}
```

Перевіряється, чи не виходить індекс за межі списку. Якщо індекс некоректний, генерується виняток.

Це захищає внутрішній масив `_items` від некоректного доступу.

### Приклад 2 — DateTime

```csharp
if ((uint)kind > (uint)DateTimeKind.Local)
{
    ThrowInvalidKind();
}
```

Перевіряється допустимість значення `DateTimeKind`. Якщо значення некоректне, генерується виняток.

Такий підхід не дозволяє створювати об'єкти з некоректним внутрішнім станом.

У цих класах валідація реалізована за допомогою умов `if` та винятків. Такий підхід дозволяє одразу повідомити програміста про неправильні дані.

## 4. Загальні висновки

Під час роботи було проаналізовано класи `List<T>` та `DateTime` з open-source проєкту .NET Runtime.

В обох класах використовується принцип інкапсуляції: внутрішні дані приховані, а доступ до них здійснюється через публічні властивості, методи та індексатори.

`List<T>` контролює доступ до внутрішнього масиву та перевіряє індекси перед отриманням елементів. `DateTime` приховує внутрішнє представлення дати та перевіряє вхідні параметри.

Валідація за допомогою умов та винятків дозволяє запобігати некоректним операціям і захищати внутрішній стан об'єктів.

Отже, інкапсуляція та валідація роблять класи більш надійними, передбачуваними та безпечними у використанні.
