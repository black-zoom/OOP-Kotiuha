### Аналіз open-source проєктів

1. **.NET Runtime — Dictionary<TKey, TValue>**

Посилання на вихідний код:
https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs

У методі ToDictionary використовується Dictionary для перетворення послідовності елементів у колекцію пар ключ-значення.

**Контекст:** створення словника, у якому кожному ключу відповідає певне значення. Це дозволяє зручно організувати дані та швидко отримувати потрібні елементи за ключем.

**Причина вибору:** Dictionary забезпечує швидкий пошук за ключем. На відміну від List, не потрібно перебирати всі елементи для знаходження потрібного значення.

**Складність:** додавання та пошук за ключем у середньому O(1). Створення словника з n елементів — O(n). У найгіршому випадку операції можуть мати складність O(n).

**Особливості:** метод ToDictionary підтримує використання власного IEqualityComparer<TKey> для порівняння ключів. Якщо послідовність містить повторювані ключі, виникає виняток ArgumentException.

2. **.NET Runtime — HashSet<T>**

Посилання на вихідний код:
https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs

У методі ToHashSet використовується HashSet для перетворення послідовності елементів у множину унікальних значень.

**Контекст:** створення колекції, яка не містить повторюваних елементів. Такий підхід зручний для усунення дублікатів у послідовностях даних.

**Причина вибору:** HashSet автоматично не допускає дублювання елементів та забезпечує швидку перевірку їх наявності. На відміну від List, не потрібно вручну перевіряти кожен елемент на повторення.

**Складність:** додавання та перевірка наявності елемента у середньому O(1). Створення множини з n елементів — у середньому O(n). У найгіршому випадку операції можуть мати складність O(n).

**Особливості:** метод ToHashSet підтримує використання власного IEqualityComparer<T>. Якщо до множини додається елемент, який уже існує, він не додається повторно.

3. **AutoMapper — Dictionary та HashSet**

Посилання на вихідний код:
https://github.com/LuckyPennySoftware/AutoMapper/blob/main/src/AutoMapper/Configuration/MapperConfiguration.cs

У класі MapperConfiguration використовуються обидві колекції:

- Dictionary<TypePair, TypeMap> — для зберігання відповідностей між парами типів та налаштуваннями їх перетворення.
- HashSet<TypeMap> — для відстеження шляху типів під час побудови маппінгу.

**Контекст:** бібліотека AutoMapper виконує перетворення об'єктів одного типу в об'єкти іншого типу. Для цього необхідно зберігати налаштування відповідностей між типами та відстежувати типи, які беруть участь у побудові маппінгу.

**Причина вибору:** Dictionary дозволяє швидко знаходити налаштування перетворення за парою типів. HashSet використовується для зберігання унікальних елементів шляху маппінгу та швидкої перевірки їх наявності. Використання List для таких операцій вимагало б послідовного пошуку елементів.

**Складність:** пошук, додавання та перевірка наявності елементів у Dictionary і HashSet у середньому O(1). У найгіршому випадку через хеш-колізії складність може становити O(n).

**Особливості:** використовуються типи TypePair та TypeMap. Для коректної роботи колекцій важливо, щоб ці типи забезпечували правильне порівняння та обчислення хеш-кодів. У коді AutoMapper також використовуються інші колекції, зокрема List та масиви, залежно від призначення даних.

| Операція | List | Dictionary | HashSet |
|---|---|---|---|
| Додавання | O(1)* | O(1)* | O(1)* |
| Пошук за значенням | O(n) | O(n) | O(1)* |
| Пошук за ключем | N/A | O(1)* | N/A |
| Видалення | O(n) | O(1)* | O(1)* |
| Перевірка наявності | O(n) | O(1)* | O(1)* |

* Середня або амортизована складність. У найгіршому випадку через хеш-колізії операції Dictionary та HashSet можуть мати складність O(n). Додавання в кінець List амортизовано виконується за O(1).
